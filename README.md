# 📸 Фотостудия — информационная система

Настольное приложение для учёта работы фотостудии: клиенты, фотографы, услуги, локации,
оборудование, фотосессии и отзывы. Три роли с разными правами: **админ**, **клиент**, **фотограф**.


БЕЗ БАЗЗЫ ДАННЫХ ПРОЕКТ НЕ ЗАПУСТИТЬСЯ
## Возможности

- Вход по логину и паролю (пароли хранятся как PBKDF2 с солью)
- Администратор: просмотр всех таблиц, добавление клиентов и фотосессий, редактирование
  (двойной щелчок), удаление (Delete), графики выручки и популярности услуг, топ фотографов
- Клиент: свои фотосессии, услуги, локации, написание отзывов, отчёт «Мои расходы»
- Фотограф: свои съёмки, отзывы о себе, отчёт «Мои доходы»
- Поиск по таблице (Ctrl+F), сортировка по клику на заголовок, экспорт в Excel (Ctrl+E)
- Светлая и тёмная тема (Ctrl+T), обновление данных (F5)
- Запросы к базе идут в фоновом потоке, интерфейс не зависает


## Запуск

```bash
pip install -r requirements.txt
cp .env.example .env      # впиши параметры подключения к MySQL
python main.py
```

Нужны MySQL-сервер и база `photo_bd` (положи сюда свой дамп: `mysqldump -u root -p photo_bd > photo_bd.sql`).

### Если в базе остались старые пароли (SHA-256)

Они продолжают работать. Чтобы при первом входе они автоматически заменились на новые,
расширь колонку:

```sql
ALTER TABLE пользователь MODIFY пароль VARCHAR(255);
```

## Ожидаемая структура БД (по запросам в коде)

`клиент`, `фотограф`, `услуга`, `локация`, `оборудование`, `фотосессия`, `отзыв`,
`пользователь` (логин, пароль, активен, id_роли, id_клиента, id_фотографа), `роль`.
Названия статусов фотосессий лежат в `config.py` (`STATUS_PLANNED`, `STATUS_DONE`, `STATUS_CANCELLED`).

## Структура проекта

| Файл | Назначение |
|---|---|
| `main.py` | точка входа, переключение «вход ↔ приложение» |
| `login.py` | окно авторизации |
| `app.py` | главное окно, вкладки, формы, отчёты, графики |
| `auth.py` | хеширование паролей и вход |
| `db.py` | запросы к MySQL (только с параметрами) |
| `config.py` | настройки из `.env`, роли и статусы |

## Что улучшено по сравнению с первой версией

- Все SQL-запросы параметризованы (раньше часть была через f-строки — риск SQL-инъекций)
- Пароль и доступ к БД вынесены из кода в `.env`
- Пароли: PBKDF2-HMAC-SHA256 с солью вместо голого SHA-256, старые хеши обновляются сами
- Удаление и правка записей теперь реально работают (раньше были заглушками)
- Настоящая тёмная тема, поиск, сортировка, проверка вводимых данных
- Проверка занятости фотографа при добавлении фотосессии
- Графики выручки доступны только администратору
- Код разделён на модули, добавлена обработка ошибок БД
